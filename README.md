## 📚 진행 방식

1. 팀 대표 1명이 공통 저장소를 Fork하고 나머지 팀원들을 Collaborator로 초대합니다. 각 팀원은 팀 Fork 저장소를 Clone한 뒤, `week7-이름`, `week8-이름`처럼 주차별 개인 작업 브랜치를 생성합니다.
2. 팀에서 역할을 나누고 요구사항에 맞춰 ERD와 API를 설계합니다. 제공된 Spring Boot 초기 코드와 Thymeleaf 화면을 바탕으로 기능을 구현합니다.
3. 매주 **팀원별로 PR을 최소 1개씩 팀 Fork 레포지토리의 `main` 브랜치로** 보냅니다. PR에는 구현 내용, 고민한 점, 테스트 결과와 화면 캡처, 리뷰받고 싶은 부분을 작성합니다.
4. 팀원들이 서로의 PR을 리뷰하고 수정 사항을 반영한 뒤 직접 Merge합니다. 모든 팀원의 작업이 팀 Fork의 `main`에 반영되면, 팀 대표가 **공통 레포지토리의 본인 팀 브랜치(`team1`, `team2`, `team3`)로 최종 PR**을 보냅니다.
5. Team Member의 리뷰를 반영하고 최종 PR을 Merge합니다. 리뷰 수정 사항까지 팀 Fork의 `main`에 반영한 후, 해당 브랜치의 최신 코드를 기준으로 다음 주차 작업을 시작합니다.

## 📝 PR 작성 규칙

매주 개인 PR과 팀 최종 PR을 아래 제목 형식에 맞춰 작성해 주세요.

**① 팀 내부 개인 PR**
- 제목 형식: `[N주차 - 이름] 구현한 기능`
- 예시: `[7주차 - 이채영] 스터디 등록 및 조회 기능 구현`
- PR 대상: 팀 Fork 레포지토리의 `main` 브랜치

**② 팀 제출 PR**
- 제목 형식: `[N조] 2026 GDG Spring Novice Study Toy Project - N주차`
- 예시: `[1조] 2026 GDG Spring Novice Study Toy Project - 7주차`
- PR 대상: GDGoC 공통 레포지토리의 본인 팀 브랜치 (`team1`, `team2`, `team3`)

PR 작성 시 해당 유형의 템플릿을 사용하고, 구현 내용과 테스트 결과 등을 작성해 주세요. 팀 최종 PR에는 팀원별 담당 기능과 주요 작업 내용도 포함합니다.

## ▶️ 로컬 실행

1. Java 17을 준비합니다. 프로젝트 폴더에서 실행하면 H2 데이터는 `data/gdgoc.mv.db`에 저장되며 앱을 재시작해도 유지됩니다.
2. Google OAuth 웹 클라이언트의 승인된 리디렉션 URI에 `http://localhost:8080/login/oauth2/code/google`을 등록합니다. 테스트 모드라면 로그인할 계정을 테스트 사용자로 추가합니다.
3. 프로젝트 루트에서 `.env.example`을 `.env`로 복사하고, 두 항목에 본인의 Google OAuth 클라이언트 ID와 시크릿을 입력합니다. `.env`는 Git에 올리지 않습니다.
4. 프로젝트 루트에서 아래 명령으로 실행합니다.

```powershell
.\gradlew.bat bootRun
```

[로그인 화면](http://localhost:8080/login)에서 Google로 로그인합니다.
